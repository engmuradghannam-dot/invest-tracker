# إدارة المشاريع الاستثمارية

متابعة رأس المال، الأرباح الدورية، جداول الاستحقاق، والدفعات — مع تنبيهات بريدية قبل موعد كل دفعة.

## التشغيل

```bash
# 1. قاعدة البيانات
docker compose up -d

# 2. الخادم
cd server
cp .env.example .env      # عدّل DATABASE_URL وبيانات SMTP
npm install
npm run db:push           # ينشئ الجداول
npm run db:seed           # يُدخل المشاريع الثلاثة
npm run dev               # http://localhost:4000

# 3. الواجهة
cd ../client
npm install
npm run dev               # http://localhost:5173
```

## قرارات تصميمية

**المال بالفلس كأعداد صحيحة.** كل المبالغ تُخزَّن `BigInt` بالفلس (١ دينار = ١٠٠٠ فلس). لا `Float` في أي مكان — `0.1 + 0.2 !== 0.3` في الحساب العائم، وفي سجل مالي هذا خطأ لا يُغتفر.

**النسبة بالنقاط الأساسية.** `7.5%` تُخزَّن `750`. عدد صحيح، بلا كسور عائمة.

**جدول الاستحقاق يُولَّد عند الإنشاء.** ليس محسوباً وقت العرض — لأن الدفعات ترتبط بصفوف حقيقية، والجدول قد يُعدَّل يدوياً لاحقاً.

**`addMonths` يثبّت اليوم.** ٣١ يناير + شهر = ٢٨ فبراير، لا ٣ مارس.

**إعادة التوليد لا تمسّ استحقاقاً عليه دفعة.** حذفه يعني فقدان سجل دفع حقيقي.

## الاختبارات

```bash
cd server && npm test
```

تغطي: تحويل المال، حساب الربح، تثبيت التواريخ، توليد الجدول (مغلق ومفتوح)، حالات الاستحقاق، والملخص المالي.

## المرفقات

الإيصالات تُرفع مع الدفعة أو تُلحق بالمشروع. صور و PDF فقط، حتى ١٠ ميغابايت للملف.

الملف يُخزَّن باسم عشوائي (UUID) على القرص، والاسم الأصلي يبقى في قاعدة البيانات. هذا يمنع تصادم الأسماء ومحاولات اجتياز المسار عبر اسم ملف مُعدّ. عند التنزيل يُبنى المسار من `basename` للسجل، لا من مدخلات الطلب.

للنشر السحابي: `UPLOAD_DIR` لازم يكون على تخزين دائم (volume)، وإلا تضيع الإيصالات مع كل إعادة نشر.

## تعديل المشروع

التعديل لا يمسّ الجدول. بعد الحفظ، «إعادة توليد الجدول» تطبّق الشروط الجديدة — لكن أي استحقاق عليه دفعة مسجّلة يبقى بمبلغه القديم.

هذا مقصود: الدفعة سجل لما حدث فعلاً. لو أردت تعديل استحقاق مدفوع، احذف دفعته أولاً.

## ما لم يُبنَ بعد

- تكامل Google Drive (`storage: "gdrive"` محجوز في النموذج)
- المصادقة وتعدد المستخدمين — **لا تنشر على الإنترنت قبلها**
- تصدير Excel / PDF
